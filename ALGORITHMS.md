## Алгоритмы генерации

### DFS (Depth-First Search)

**Описание:** Рекурсивный поиск в глубину — создаёт длинные извилистые коридоры.

**Принцип работы:**
- Начинает с камеры (0,0) и помечает её как проход
- Случайно перемешивает направления движения (вверх, вниз, влево, вправо)
- Рекурсивно углубляется в непосещённые соседние камеры
- При встрече со стеной пробивает перегородку между текущей и следующей камерой
- При тупике возвращается назад (backtrack) и пробует другие направления

**Сложность:**
- Время: O(W × H)
- Память: O(W × H) — стек рекурсии

**Шаги алгоритма:**
1. Создать логическую сетку камер размером CW × CH
2. Начать с камеры (0, 0)
3. Пометить текущую камеру как посещённую
4. Случайно перемешать 4 направления движения
5. Для каждого направления:
- Если соседняя камера в границах и непосещённая:
- Пробить перегородку между камерами (carvePassage)
- Рекурсивно запустить DFS от новой камеры
6. Когда все соседи посещены — возврат назад

**Результат:** Лабиринт с длинными коридорами и малым количеством ответвлений. Один главный путь с множеством тупиковых боковых веток.

### Prim True

**Описание:** Классический алгоритм Прима

**Принцип работы:**
- Ведёт список всех "граничных" рёбер между посещёнными и непосещёнными камерами
- На каждом шаге случайно выбирает ребро из фронтира
- Пробивает перегородку соответствующего ребра
- Добавляет новые рёбра от подключённой камеры к её непосещённым соседям

**Сложность:**
- Время: O(W × H) — случайный выбор из списка
- Память: O(W × H) — фронтир рёбер

**Шаги алгоритма:**
1. Начать с камеры (0, 0)
2. Добавить все рёбра этой камеры в фронтир
3. Пока фронтир не пуст:
- Выбрать случайное ребро из фронтира
- Если целевая камера непосещённая:
- Пробить перегородку между камерами
- Пометить целевую камеру как посещённую
- Добавить её рёбра в фронтир
4. Удалить выбранное ребро из фронтира

**Результат:** Более сбалансированный лабиринт с равномерным распределением коридоров. Много коротких тупиков.

### Prim Simplified

**Описание:** Упрощённая версия Прима. Вместо фронтира рёбер использует список посещённых камер.

**Принцип работы:**
- Ведёт список всех посещённых камер
- На каждом шаге выбирает случайную посещённую камеру
- Если у неё есть непосещённые соседи — соединяет с одним из них
- Если соседей нет — удаляет камеру из активного списка

**Сложность:**
- Время: O(W × H) в среднем
- Память: O(W × H)

**Отличия от Prim True:**
- Работает со списком **камер**, а не **рёбер**
- Проще в реализации
- Немного другой порядок обхода камер

**Шаги алгоритма:**
1. Начать с камеры (0, 0), добавить в список visitedCells
2. Пока список не пуст:
- Выбрать случайную камеру из списка
- Получить её непосещённых соседей
- Если соседи есть:
- Выбрать случайного соседа
- Пробить перегородку и пометить соседа
- Добавить соседа в visitedCells
- Если соседей нет:
- Удалить камеру из списка

**Результат:** Практически идентичен Prim True, но генерируется с немного другим порядком обхода.

### Prim Modified

**Описание:** Модифицированная версия Прима с использованием пар (родитель, кандидат) вместо списка рёбер.

**Принцип работы:**
- Ведёт фронтир узлов-кандидатов с указанием родительской камеры
- Стартует со случайной камеры (а не всегда с (0,0))
- На каждом шаге выбирает пару (parent → child) из фронтира
- Соединяет родителя с кандидатом

**Сложность:**
- Время: O(W × H)
- Память: O(W × H)

**Отличия от других версий Прима:**
- Случайная стартовая позиция (не всегда (0,0))
- Хранит явную связь parent → child

**Шаги алгоритма:**
1. Выбрать случайную стартовую камеру (sx, sy)
2. Добавить её соседей в фронтир как пары (sx,sy) → (neighbor)
3. Пока фронтир не пуст:
- Выбрать случайную пару из фронтира
- Если кандидат непосещён:
- Пробить перегородку между родителем и кандидатом
- Пометить кандидата как посещённого
- Добавить соседей кандидата в фронтир

**Результат:** Визуально похож на Prim True/Simplified, но с другой начальной точкой.

## Алгоритмы решения

### BFS (Breadth-First Search)

**Описание:** Алгоритм поиска кратчайшего пути в невзвешенном графе, в лабиринте с одинаковой стоимостью шага всегда находит маршрут минимальной длины.

**Сложность:**
- Время: O(W × H)
- Память: O(W × H)

**Как работает:**
1. Добавить стартовую ячейку в очередь и пометить её как посещённую.
2. Извлекать ячейку из очереди и просматривать всех соседей (4‑соседство).
3. Для каждого проходимого и ещё не посещённого соседа:
- Пометить как посещённого.
- Записать предка в таблицу `previous`.
- Добавить соседа в очередь.
4. При достижении финиша восстановить путь по таблице `previous` (от финиша к старту).

**Когда использовать:**
- Когда все рёбра имеют одинаковый вес.
- Когда нужен гарантированно кратчайший путь по числу шагов.
- Когда важна простота реализации и предсказуемое поведение.

---

### Dijkstra

**Описание:** Алгоритм поиска кратчайшего пути с неотрицательными весами рёбер.

**Сложность:**
- Время: O((W × H) × log(W × H)) с приоритетной очередью
- Память: O(W × H)

**Как работает:**
1. Инициализировать дистанции: стартовая = 0, остальные = ∞
2. Использовать приоритетную очередь для выбора ячейки с минимальной дистанцией
3. Для каждой ячейки:
- Пометить как посещённую
- Обновить дистанции соседей (релаксация)
- Если сосед непроходим или посещён — пропустить
4. Восстановить путь по таблице `previous`

**Когда использовать:**
- Когда нужен кратчайший путь
- Когда веса рёбер положительны
- Когда производительность важнее скорости поиска

### A* (A-Star)

**Описание:** Эвристический поиск, который комбинирует реальную дистанцию и эвристику.

**Сложность:**
- Время: O((W × H) × log(W × H)) в худшем случае, но часто быстрее на практике
- Память: O(W × H)

**Формула оценки:**

```
f(n) = g(n) + h(n)
```

где:
- g(n) = расстояние от старта до ячейки n
- h(n) = манхэттенская дистанция от n до цели, h(n) = |n.x - goal.x| + |n.y - goal.y|
- f(n) = общая оценка

**Как работает:**
1. Инициализировать f-оценки: стартовая = h(start)
2. Использовать набор `openSet` для кандидатов
3. Выбирать ячейку с минимальной f-оценкой
4. Для каждого соседа:
- Если новый g-путь лучше — обновить
- Добавить в openSet
5. Восстановить путь

**Когда использовать:**
- Когда нужен кратчайший путь И скорость
- Когда есть явная цель
- Когда веса однородны (все = 1)
- Для игр, навигации, планирования маршрутов

## Технические детали реализации

### Формат лабиринта

**Входные параметры:** W × H (ширина × высота без рамки)

**Выходная матрица:** (W+2) × (H+2) с полной рамкой стен по периметру

**Примеры:**
- Запрос 3×3 → итоговая матрица 5×5
- Запрос 10×10 → итоговая матрица 12×12

### Идеальность лабиринта

Все реализованные алгоритмы гарантируют **идеальный лабиринт** - между любыми двумя точками существует ровно один путь.
